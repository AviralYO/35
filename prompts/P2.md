# P2: prompts
1. List splits

   > Use the prolog-dev skill. For P2, first write only split_nonempty/3. It should split a list into a nonempty left part and a nonempty right part, trying every possible boundary on backtracking. Keep the numbers in their original order. Empty and one-element inputs should just fail.

2. Arithmetic operations

   > Write combine/5 for one arithmetic operation at a time: operator, left value, right value, result and display precedence. Support +, -, * and /. Division must reject a zero divisor and any non-integer result. Subexpressions can be negative, so check negative operands too.

3. Expression trees

   > Can you write expression/3 using the split and arithmetic predicates? Its arguments should be the input numbers, an expression tree and its integer value. Try every binary tree over the numbers in order. Work with the tree directly; don't make a string and parse it back to evaluate it.

4. Operand parentheses

   > Write just operand_text/4 for a child tree, the parent's precedence, which side it's on, and the resulting string. A left child needs parentheses when its precedence is lower. A right child needs them when its precedence is equal or lower. A number should never get parentheses. This distinction needs to preserve different expression trees.

5. Expression formatting

   > Now write expression_text/2 using operand_text/4. Turn a number or expression tree into an SWI-Prolog string with no spaces. Follow the PDF's parentheses rules exactly, including the difference between 1+(2+3) and 1+2+3.

6. One equation

   > Add generate_equation/2. Try each possible position for the equals sign, generate a valid integer expression on each side, and return an equation only when their values match. Every number must be used once in the given order. If there is no answer, it should fail without an error or an infinite loop.

7. All equations

   > Write all_equations/2 using the equation generator. Collect every answer, remove duplicates and sort the strings with sort/2. Return an empty list when there are no equations.

8. Equation count

   > Add count_equations/2. Use the completed all_equations/2 predicate so that the count refers to distinct canonical equation strings.

9. Test file

   > Write one P2 test file. Include the exact seven equations for [4,2,5,3], the no-answer example [2,3,4], and [2,4,8]. Add cases for empty and singleton lists, zero, negative intermediate values, and division that would be fractional inside a larger expression. Check the parentheses rules and compare small inputs with an independently written reference generator.

10. Review

    > Review P2 for completeness and duplicate answers. In particular, check that division is exact at every node, both sides preserve the input order, the result is a string, and right operands with equal precedence keep their parentheses. Also check that loading the file prints nothing. Report issues without replacing the entire implementation.
